# ADR-011: แก้ไขแผนงาน ย้ายกลุ่มอิสระ จำผู้ลงนาม และจัดหัวเว็บ/เมนูใหม่

สถานะ: ใช้งาน (2026-11-09) · แทนที่ส่วน "ย้ายกลุ่มได้เฉพาะกลุ่มตน" ของ ADR-006

## บริบท
ผู้ใช้ต้องการ (1) แยกปุ่มเข้าสู่ระบบไปด้านขวาของหัวเว็บ (2) ย้ายบัตรผู้ใช้ขึ้นหัวเว็บ (3) ให้ Admin เพิ่ม/แก้ไข/ปรับรายละเอียดโครงการ-กิจกรรม และเปลี่ยนกลุ่มงานได้ (4) บันทึกข้อความ: โทรสาร → โทรศัพท์ และตัดข้อความในวงเล็บ 4 จุด (5) สีเมนูแยกหมวดชัดเจน

## การตัดสินใจ
- **ย้ายกลุ่มงานอิสระ**: เจ้าหน้าที่ทุกระดับกำหนด/ย้ายรายการของทุกกลุ่มได้ (`plans.assign` ใช้ ctx ยกสิทธิ์ภายในเฉพาะการสร้างโครงการ/กิจกรรม/งบของกลุ่มปลายทาง) ยังห้ามย้ายรายการที่มีการเบิกจ่ายแล้ว พื้นที่และไตรมาสถูกยกไปด้วย ทุกครั้งมี audit
- **แก้รายละเอียด** (`plans.updateItem`): ชื่อ หน่วยนับ เป้าหมาย หมายเหตุ เฉพาะรายการของกลุ่มตนหรือที่ยังไม่มีกลุ่ม ใช้ version กันแก้ทับ เป้าหมายใหม่ต้องเท่ากับผลรวมเป้ารายพื้นที่ (ถ้ากำหนดไว้)
- **ปรับงบ** (`plans.adjustBudget`): ไม่แก้ยอดตามแผนของกรม บันทึกเป็น Allocation TRANSFER_IN/OUT `source=ADJUST:<itemId>` พร้อมเหตุผลและเลขหนังสือ หน้าแผนแสดง "งบปัจจุบัน" และยอดตามแผนแบบขีดฆ่าเมื่อต่างกัน ห้ามลดต่ำกว่ายอดเบิกแล้ว (ตรวจที่หน้าจอ; ยอดรวมยังตรวจโดย createAllocation)
- **เพิ่มกิจกรรม** (`plans.addItem`): ใต้หัวข้อโครงการ/กิจกรรม เป็นใบ (`manual=true`, เลขลำดับต่อท้าย `*`) แสดงป้าย "เพิ่มเอง" ลบได้ (`plans.deleteItem`) เมื่อยังไม่มีการเบิกจ่าย (soft delete) ยอดรวมของหนังสือแผนไม่เปลี่ยน
- **ผู้ลงนาม (ข้อ 7)**: เมื่อสร้าง/แก้บันทึกข้อความ ระบบจำหัวหน้ากลุ่ม/ผู้รักษาการล่าสุดของกลุ่มอัตโนมัติ และมีปุ่ม "บันทึกเป็นค่าประจำกลุ่ม" (`memos.saveHead`) — เก็บโทรศัพท์ด้วย ช่อง `fax` ในข้อมูลคงชื่อเดิมเพื่อเข้ากันได้ย้อนหลัง แต่แสดงเป็น "โทรศัพท์"
- **หัวเว็บ**: แถวบน = โลโก้/ชื่อ · ขนาดตัวอักษร · (ปุ่ม "เข้าสู่ระบบเจ้าหน้าที่" หรือบัตรผู้ใช้ + ออกจากระบบ) ชิดขวา; แถวล่าง = เมนูหลัก บนมือถือบัตรผู้ใช้เหลือเฉพาะอักษรย่อ
- **เมนูเจ้าหน้าที่**: 4 หมวด ใช้ 2 สี (เขียว/ทอง) แยกด้วยเฉด — งานประจำ (เขียวเข้ม) · ติดตามและรายงาน (เขียวอ่อน) · ข้อมูลอ้างอิงและตั้งค่า (ทองอ่อน) · ผู้ดูแลระบบ (ทองเข้ม) เมนูปัจจุบันพื้นทึบตามสีหมวด
- Schema: PlanItems เพิ่ม `manual`, `note` (SCHEMA_VERSION 2026.11.09-2)

## ผลที่ตามมา
- ความรับผิดชอบเรื่องการย้ายกลุ่มอยู่ที่เจ้าหน้าที่ทุกคน ตรวจย้อนได้จาก AuditLog (`plan.assign` before.moved)
- งบปรับปรากฏในรายงานเหมือนการโอนงบปกติ
