# ADR-007 เป้าการเบิกจ่ายที่ตั้งค่าได้ และกำหนดเดือนที่ต้องเบิกครบรายกิจกรรม

วันที่ 7 พ.ย. 2569 — สถานะ: ใช้งาน

## ปัญหา
เป้าการเบิกจ่ายเดิมมาจากหลายแหล่ง (เป้ารายไตรมาสของแต่ละโครงการ, แผนรายไตรมาสของกิจกรรม, วันกำหนดอบรมที่เขียนในโค้ด)
ผู้ใช้ต้องการตั้งเป้าเองได้ทั้งแบบรายไตรมาสและแบบ "เบิกให้ครบภายในเดือน…" และให้ทุกส่วนของระบบใช้เป้าเดียวกัน

## การตัดสินใจ
1. **เป้าของปีงบประมาณ** เก็บใน `Settings` คีย์ `spendTarget:<ปี>` (JSON `SpendTarget`)
   - `quarter`: ร้อยละสะสมสิ้นไตรมาส 1–4 (ต้องไม่ลดลง ไม่เกิน 100)
   - `deadline`: ถึง `pct`% ภายในสิ้นเดือน `month` (เพิ่มเท่ากันทุกเดือน) แล้วไต่ถึง 100% ในเดือน ก.ย. ถ้า pct < 100
   - ไม่ตั้ง = `defaultQuarterTargets` (30,55,80,100); แก้ได้เฉพาะ Mini Super / Super Admin
2. **รายกิจกรรม** คอลัมน์ `Activities.dueMonth`: 1–12 = ต้องเบิกครบ 100% ภายในเดือนนั้น, 0 = ค่าเริ่มต้น, -1 = ตามเป้าของปี
   - ค่าเริ่มต้นของกิจกรรมอบรม/ประชุม/สัมมนา (`MEETING_RE`) = มิ.ย. ตามมาตรการเร่งรัดฯ
3. ลำดับที่ใช้คำนวณแผน (`activityPlan`): dueMonth ที่ตั้ง > แผนรายไตรมาสของกิจกรรม (ถ้ามี) > อบรม = มิ.ย. > เป้าของปี
4. ทุกส่วนใช้ฟังก์ชันเดียวกัน: แถบเป้า, "เทียบแผน", KeyFacts, กราฟสะสม, risk flag, รายงาน
5. `Project.quarterTargets` ยังเก็บไว้เพื่อความเข้ากันได้ แต่ไม่ใช้คำนวณแล้ว

## ผลกระทบ
- กิจกรรมอบรม/ประชุมมีแผนสะสมสูงขึ้น (ครบ มิ.ย.) แผนรวมของหน่วยงานจึงสูงกว่าเดิม — ตรงกับมาตรการจริง
- ต้องรัน setup หลัง deploy เพื่อเพิ่มหัวคอลัมน์ `dueMonth`
