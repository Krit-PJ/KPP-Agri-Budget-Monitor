# คู่มือปฏิบัติการ: rotate credential, ย้ายเจ้าของ, incident

## เปลี่ยนรหัส Super Admin
1. เปิด Apps Script editor แล้วสร้างไฟล์ชั่วคราว `Tmp.gs`:
   `function changePw(){ setSuperAdmin('ชื่อผู้ใช้', 'รหัสใหม่อย่างน้อย8ตัว'); }`
2. รัน `changePw` แล้ว**ลบ `Tmp.gs` ทันที**
3. token เดิมของ Super Admin ถูกเพิกถอนทันที (ระบบเพิ่ม `SUPER_TV`)

## Rotate token secret (เมื่อสงสัยว่า token รั่ว)
1. Project Settings → Script properties → ลบ `TOKEN_SECRET`
2. ทุกคนจะถูกออกจากระบบ และ secret ใหม่จะถูกสร้างเองเมื่อมี request ถัดไป

## พบ secret ใน repository
1. หยุดใช้ secret นั้นทันที (เปลี่ยนรหัส หรือ rotate ตามหัวข้อข้างบน)
2. ลบไฟล์ใน commit ใหม่ **ห้ามแก้ Git history เอง** ปรึกษาเจ้าของงานก่อนใช้ git filter-repo
3. บันทึกเหตุการณ์ใน `00_System/incidents`

## ระงับผู้ใช้ด่วน (เช่น เบอร์โทรถูกนำไปใช้)
1. Super Admin → ผู้ใช้และสิทธิ์ → ผู้ใช้ → ระงับ (มีผลทันที token เดิมใช้ไม่ได้)
2. ตรวจ "รายงานการเข้าสู่ระบบ" และ "บันทึกการใช้งาน" ของผู้ใช้นั้นย้อนหลัง
3. รายการที่ไม่ถูกต้อง ให้ Super Admin ยกเลิกแบบ void พร้อมเหตุผล

## ย้ายบัญชีเจ้าของข้อมูล (เช่น ผู้ถือบัญชีย้ายงาน)
1. บัญชีเดิมแชร์โฟลเดอร์รากให้บัญชีใหม่เป็น Editor แล้วโอนสิทธิ์เจ้าของ (Transfer ownership) ทั้งโฟลเดอร์และไฟล์
   - Gmail ส่วนตัวโอนเจ้าของข้ามบัญชีได้ แต่ผู้รับต้องกดยอมรับ
2. บัญชีใหม่สร้างโปรเจกต์ Apps Script ใหม่ตามคู่มือ deploy ข้อ 2 (โปรเจกต์ผูกกับผู้ deploy)
3. คัดลอก Script properties ที่จำเป็น (`ROOT_FOLDER_ID`, `FILE_IDS`, `SUPER_USER`, `SUPER_HASH`, `SUPER_TV`) จากโปรเจกต์เดิม
   - **ห้ามคัดลอก `TOKEN_SECRET`** ปล่อยให้ระบบสร้างใหม่
4. Deploy แล้วอัปเดต `KPP_API_URL` ใน GitHub
5. ปิด deployment ของโปรเจกต์เดิม

## ระดับเหตุการณ์และการตอบสนอง
| ระดับ | ตัวอย่าง | ทำทันที |
|---|---|---|
| สูง | ยอดเงินผิดจำนวนมาก, ข้อมูลส่วนบุคคลรั่ว, มีผู้ใช้ที่ไม่ได้รับอนุญาต | ระงับผู้ใช้หรือปิด deployment, แจ้งเจ้าของงานและ DPO, เก็บหลักฐาน |
| กลาง | นำเข้าผิดไฟล์, trigger ไม่ทำงาน | ยกเลิกรายการ (void), รัน trigger ด้วยมือ |
| ต่ำ | ข้อความแสดงผิด | แก้ใน release ถัดไป |

กรณีข้อมูลส่วนบุคคลรั่ว พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคลกำหนดให้แจ้ง สคส. ภายใน 72 ชั่วโมงในกรณีที่มีความเสี่ยง ให้ปรึกษา DPO ของหน่วยงาน
