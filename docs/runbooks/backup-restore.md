# สำรองและกู้คืนข้อมูล

## การสำรองอัตโนมัติ
- trigger `dailyMaintenance` ทำงานทุกวันเวลา 02:00 น. (เวลาไทย)
  - คัดลอกไฟล์ทั้ง 4 ไปที่ `99_Archive/backup/YYYY-MM-DD/`
  - สร้าง snapshot สาธารณะลงไฟล์ REPORTING
- สำเนาที่เก่ากว่า `backupRetentionDays` (ค่าเริ่มต้น 30 วัน) ถูกย้ายไปถังขยะ และกู้คืนจากถังขยะได้อีก 30 วัน
- ดูเวลาสำรองล่าสุดได้ที่ "ตั้งค่าระบบ → สถานะระบบ"

## กู้คืนทั้งไฟล์ (เช่น ข้อมูลเสียหายหรือถูกลบ)
1. ประกาศหยุดบันทึกข้อมูลชั่วคราว และบันทึกเวลาเริ่มเหตุการณ์
2. ใน Drive ให้เปิด `99_Archive/backup/<วันที่ก่อนเกิดเหตุ>/` แล้วคัดลอกไฟล์ที่ต้องการกู้ (เช่น `KPP_ABM_CORE_2026-11-04`)
3. เปลี่ยนชื่อไฟล์ปัจจุบันเป็น `..._broken_<วันที่>` เก็บไว้เป็นหลักฐาน **ห้ามลบ**
4. ย้ายสำเนาไป `00_System` แล้วตั้งชื่อเป็นชื่อเดิม (`KPP_ABM_CORE`)
5. ใน Apps Script ไปที่ Project Settings → Script properties → แก้ `FILE_IDS` ให้ชี้ไป ID ของไฟล์ใหม่
6. รัน `setup` เพื่อตรวจ schema
7. ล็อกอิน Super Admin → ตั้งค่าระบบ → สถานะระบบ → "สร้างสรุปข้อมูลสาธารณะใหม่"
8. ตรวจ reconciliation โดยสุ่ม 5 โครงการ เทียบยอดกับรายงาน GFMIS ล่าสุด
9. นำเข้ารายงานที่เกิดหลังเวลาสำรองซ้ำ (ระบบไม่นับยอดซ้ำ)

## กู้คืนบางรายการ
- รายการเบิกจ่ายที่บันทึกผิด ให้ใช้ "ยกเลิก/แก้ไข" (void-and-replace) แทนการแก้ในชีต
- ห้ามแก้ตัวเลขในชีตโดยตรง เพราะ audit จะไม่ตรงกับข้อมูล

## ซ้อมกู้คืน (ทุกไตรมาส)
1. คัดลอก backup ล่าสุดไปไว้ในโฟลเดอร์ทดสอบแยก
2. สร้างโปรเจกต์ Apps Script สำหรับทดสอบ ใช้ `ROOT_FOLDER_ID` ของโฟลเดอร์ทดสอบ แล้วรัน `setup`
3. แก้ `FILE_IDS` ให้ชี้ไปไฟล์สำเนา แล้วเปิดหน้าเว็บโหมด dev ด้วย `config.js` ที่ชี้ไป URL ทดสอบ
4. ตรวจยอดรวมในหน้าแรกว่าตรงกับระบบจริงในวันที่สำรอง
5. บันทึกผลการซ้อม (วันที่ ผู้ทำ เวลาที่ใช้ ปัญหาที่พบ) ไว้ใน `00_System/restore-drills`
